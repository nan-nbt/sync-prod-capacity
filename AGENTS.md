## Language and Format Standards (Language Rules)

### Document Part
This project requires all specification documents, explanatory documents, and chapter contents generated by AI to:

- **Must be written in [English] uniformly**
- Proper nouns can retain English (e.g., API, Database, Service)
- Documents must maintain consistent format structure (title levels, lists, chapter order)
- Including template files, please adjust to [English] format

### Prohibited:
- Prohibit writing complete chapters in English (unless explicitly requested by the user)

### Interaction with AI Process
- When users interact with AI, [English] is the primary language, so AI responses should also be primarily in [English]
- Proper nouns still retain English

## AI Specification Integrity Principle

All AI systems must follow the integrity principles below during any Plan generation process.

### Scope

This applies to all Plan generation sources, including but not limited to:

- `/specs/.../spec.md`
- `/docs/...`
- Design details provided in the `/speckit.plan` prompt
- Any section explicitly marked as core logic or immutable

### Immutable Block Definition

If any of the following content types appear:

- `<specification>`
- `[UI Specification]`
- Full SQL block definitions
- ACL / permission filtering conditions
- Explicitly defined layout structures
- Any section marked as "core logic", "do not modify", or "development basis"

Then AI must:

1. Preserve the content verbatim and in full
2. Not summarize it
3. Not optimize it
4. Not refactor it
5. Not rewrite it into another implementation approach

### Deviation Handling

If technical constraints require a change, AI must:

- Explicitly record it in a Deviation Log
- Include the original content and the reason for modification
